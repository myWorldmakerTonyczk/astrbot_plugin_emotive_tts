# 第一轮 instruction 实验报告（2026-11-02）

## 范围与固定条件

使用用户服务器已有的百炼 API Key 和 CosyEcho 音色配置，未修改在线插件、未向 QQ 发送消息。合成模型 cosyvoice-v3.5-plus，同一设计音色，同一正文：

> 你终于来啦！我等你好久了。今天过得怎么样？

生成8份 WAV。01–06对照不同指令，07–08使用 qwen-plus 根据各5条人工构造、带角色的历史生成指令，再调用相同TTS。没有使用真实私人聊天作为样本。实验发生API计费，确切金额以百炼账单为准，未作金额估算。

## 试听编号

- 01_baseline：无指令。
- 02_vague：泛泛要求富有感情、不要朗读。
- 03_raw_context：把简短背景直接放入instruction，要求自行判断。
- 04_concrete_happy：明确惊喜、笑意、轻快且不过度。
- 05_local_guidance：开头上扬、中间稍停并轻声抱怨、结尾温柔好奇。
- 06_context_sad：简短背景加轻微委屈、放慢、关心。
- 07_llm_happy：胜利归来的五条历史，由LLM生成指令。
- 08_llm_hurt：失约且曾说“先别烦我”的五条历史，由LLM生成指令。

完整指令、输入和合成结果记录在同目录manifest.json。第一轮情绪分析的两次输出未解析成功，开启结构化JSON输出并关闭思考后重试成功，失败记录仍保留；合计8次成功TTS、4次上下文分析调用。

## 已验证与未验证

1. 01–08均取得音频文件，01–06完整请求加下载耗时约1.3–1.8秒；这只是短文本单次样本，不是延迟承诺。
2. 在明确要求、结构化输出的提示下，LLM能够根据带角色的历史返回instruction；不建议直接塞原始历史而不说明任务。
3. 07的指令为“用开心、轻快的普通话语气，语速稍快”。08仍生成欢快、重逢惊喜的指令。这不必然是错误（原回复本身含积极问候），但说明上下文、正文、人格和预期情绪存在歧义，需明确谁的情绪、关系立场及冲突优先级。
4. 不能据此断言某种写法音质更好：未完成主观试听评判，每个条件只有一次生成且未固定seed。听感需用户评分，优胜方案再重复验证。
5. 没有合成SSML样本：官方SSML文档列出的音色范围是复刻音色和支持SSML的系统音色，未包含当前设计音色。不能在现有音色上把该功能视为已支持。
6. 泛泛描述、具体表演指导和句内指导均被接口接受，但接口成功不代表逐词停顿或音高被精确执行。正文标点与自然语言描述可先使用；精确毫秒停顿需要有明确支持的SSML或可选分句拼接，后者需评估连贯性。

## 暂定实现方向（待试听调整）

- context_messages=5：读取本次用户消息之前最近5条用户/助手消息；本次用户输入与待回复正文另传，不算入5条。5条不是5轮；加角色标签，保留时间顺序，不跨会话。
- 由独立配置的OpenAI兼容分析API或AstrBot已有提供商生成结构化语音指导，不绑死分析模型厂商。
- 分析任务明确“判断机器人此刻如何说”，综合人格、上下文、本次输入及回复，区分用户情绪与机器人情绪，避免强制委屈或开心。
- 输出emotion、强度、节奏、instruction等受约束字段；对当前CosyVoice限制按实际字符权重校验，不能把截断半句当作唯一修复。
- 默认短而具体的整体指导，句内指导作为候选；精细停顿标记采用能力开关，暂不默认启用。
- 合成失败回退文字；分析失败回退默认指令；不把背景与分析结果读出来。

## 支持范围与自定义接口边界

官方维护的语音适配器只实现阿里云。额外提供自定义请求头，分析API和TTS连接分别配置，密钥分别遮蔽。

请求头只能控制鉴权、路由等元信息，不能单独解决第三方API的URL、请求体和返回结构差异。阿里兼容网关可尝试替换端点并增加请求头；任意厂商需自定义HTTP请求模板/响应映射或外部兼容代理，不作内置厂商适配。请求头禁止写入日志，限制不安全的覆盖项。

## 建议试听评分

先比较01、02、04、05、06。每个样本按自然度、情绪贴合、停顿合理、音色一致各1–5分，并记下多余笑声、过度上扬、误读等问题。07–08进一步检查上下文判断是否符合角色预期。评分后再决定默认策略，不凭参数名推断效果。
