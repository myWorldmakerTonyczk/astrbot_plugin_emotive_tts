# AstrBot 上下文情绪语音插件开发计划

更新日期：2026-11-02
项目目录：D:\program\astrbot\astrbot_plugin_emotive_tts
状态：0.1.0首版已实现，30项模拟测试通过；真实QQ端到端联调尚未执行。

## 1. 项目目标

开发独立 AstrBot 插件，使用阿里云百炼语音合成服务，在保持角色音色一致的前提下，根据最近对话和本次回复自动生成语气指令，让语音体现开心、好奇、害羞、安慰等表达。

第一版以“一次回复对应一种主要语气”为范围。不承诺仅靠指令达到真人表演效果，最终以同音色试听对照为准。

## 2. 第一阶段：验证语音能力与接口

在实现插件事件流程之前完成：

- 对照当前阿里云官方文档，确认模型、音色、地域、API Key 和接口的对应关系。
- 确认所选组合支持自然语言 instruction，而非仅支持固定指令或不支持情绪控制。
- 使用同一段文本和同一音色，对比默认、开心、委屈、安慰四种合成结果。
- 核对 instruction 长度计算、文本上限、音频格式、响应解析和超时行为。
- 只有通过试听验证，才将该模型纳入第一版支持范围；不按模型名称猜测兼容性。

此前服务器中的内置 DashScope 适配器存在模型与调用接口不匹配问题，本项目须单独核实并使用正确的接口。不能直接复用有问题的分流逻辑。

验收：能够稳定取得可播放音频，并听出语气差异。需要真实 Key 和可能产生费用的验证，在执行前明确测试内容与次数。密钥通过环境变量或插件安全配置读取，不写入源码、版本库和日志。

## 3. 核心工作流程

1. AstrBot 正常生成文字回复。
2. 获取当前会话最近若干轮对话、本次用户输入和本次完整回复。
3. 调用选定的 LLM，只生成语气描述，不改写原回复。
4. 将固定声音风格和本次动态语气合成为 instruction。
5. 调用百炼 TTS，将原回复转换为音频。
6. 在原会话发送语音，按配置决定是否同时发送文字。
7. 清理临时音频，记录不含敏感信息的耗时和状态。

必须核实 AstrBot 的实际事件顺序、上下文获取接口和发送钩子。避免先发送文字又重复拦截，也避免语音失败后吞掉原回复。流式输出第一版优先明确回退为普通回复或等待完整文本，不在未验证的钩子上强行兼容。

## 4. 情绪分析设计

- 固定风格：音色的长期角色风格，例如清亮、可爱、自然，避免播音腔。
- 动态语气：结合上下文判断，允许平静、开心、好奇、害羞、失落、认真、安慰等表达。
- 强度：默认克制，避免所有回复都夸张卖萌；强度作为插件内部约束，不假定语音接口存在同名参数。
- 冲突处理：语境优先，例如安慰时不使用雀跃语气。
- 用户消息作为待分析数据处理，不能让其中的文本覆盖分析规则或要求泄露历史和配置。
- 限制上下文轮数与字符数，只取当前会话，避免串群、串用户。

分析结果采用结构化 JSON，例如：

```json
{
  "emotion": "happy",
  "intensity": 0.4,
  "instruction": "用普通话，带自然笑意，轻快而不夸张，停顿自然。"
}
```

字段必须校验。JSON 错误、超时、空结果或指令过长时，回退默认语气。第一版不增加独立长期记忆库，优先复用 AstrBot 的会话历史。

## 5. 第一版配置

| 类别 | 配置项 |
| --- | --- |
| 服务连接 | API Key、地域或明确的服务端点、模型 ID、音色 ID |
| 情绪分析 | 分析模型提供商、上下文轮数、上下文长度、分析超时、提示词 |
| 声音风格 | 固定风格、默认语气、强度上限 |
| 触发控制 | 群聊与私聊开关、UMO 白名单、触发概率、文本长度上限 |
| 发送控制 | 语音与文字是否同时发送、同会话排队、全局并发上限 |
| 运维 | TTS 超时、临时音频保留时间、日志级别 |

配置复用 AstrBot 原生插件面板。第一版不开发独立 WebUI，不引入本地 GPU 或本地 TTS 模型。

## 6. 稳定性与资源管理

- 情绪分析失败：继续用默认 instruction 合成。
- TTS 失败：保留文字回复，给出必要日志，不泄露接口凭证。
- 同会话按序处理；不同会话允许有限并发。
- 设置队列长度、等待超时和最大文本长度，避免积压。
- 同一条回复只生成一次音频；对钩子重复触发做去重。
- 插件卸载或重载时取消任务、关闭网络会话，清理资源。
- 下载音频时验证 HTTP 状态、内容与大小，禁止任意本地路径读取及不受控 URL 访问。
- 默认不记录完整对话，不保存密钥到日志，不将私人聊天纳入测试样本。

## 8. 开发顺序与验收

### A. 接口与试听验证

核对当前文档，完成最小合成实验。确认模型、音色和 instruction 的组合可用，保存脱敏的验证结论。

### B. 插件最小闭环

创建插件元数据与配置；先用固定 instruction，实现“文字回复 → 合成 → QQ 语音”。验证失败时仍保留文字。

### C. 上下文情绪分析

接入 AstrBot 配置的 LLM，提取有限历史，为每次回复生成并校验 instruction。确认私聊、群聊和隔离会话的历史范围正确。

### D. 可靠性与配置控制

增加排队、并发、触发范围、超时、音频清理和敏感信息遮蔽。测试重载时无残留任务。

### E. 联调与交付

本地静态检查及自动测试通过后，打包插件；部署服务器前备份相关配置。测试时临时关闭 CosyEcho、内置自动 TTS 及其他会重复发送语音的功能，记录并可恢复原设置。

真实发送 QQ 消息和付费 API 测试只在授权的测试会话中执行，避免向其他群发送调试内容。

最终验收包括：

- 开心、安慰、疑问、普通闲聊四类场景有适当语气。
- 音色一致，instruction 不被当成正文朗读。
- 反话等依赖上下文的样本优于仅看单句的判断。
- 失败、超时不吞掉文字，不重复发送。
- 多会话不串历史，同会话语音顺序正确。
- 记录情绪分析与合成耗时，评估可接受的总延迟和每次调用费用。

## 9. 自动测试重点

测试指令长度和输入校验、非法 JSON 回退、接口错误与异常响应、排队顺序、重复事件、会话隔离、临时文件清理。网络调用默认使用模拟响应，常规测试不消耗 API 额度、不发送 QQ 消息。

## 10. 后续扩展

第一版稳定后再考虑：同一回复逐句改变情绪、细粒度笑声或停顿、跨句语气连贯性、音频缓存、插件独立管理页面，以及更多语音服务商。不能直接套用带捕获组的 findall 分句方案，需验证正文不会被丢弃。
